# Thermi.Windows.Tests

Tests that need Windows: real named pipes, the service wrapper, the painter, the settings file shared by two writers, its mutex and its sharing, the monitors, the mouse, the window class, the overlay host and its windows, when they show, the hotkeys and their status, click-through, the menus, the tray icons and their pictures, clicks on a layered window, leaks, the log (`ThermiLogTests`, whose failures that end a process run in this assembly started again, `EndingChild.cs`, before xunit starts), both command lines (`CommandLineTests`) and the settings window's C# side. `tests/Thermi.Tests` shares `TestRecordings.cs`. They use a fake clock wherever time matters, files under their own output (`SettingsFolder.cs`), and never need admin rights. One test alone takes the real clock: `FullLoadTests`, which spins every core with `thermi cpu-load` and checks the pipe still gives a snapshot each second, so it runs after the others, by itself.

`Overlay` holds the tests of `src/Thermi/Overlay`: the host, the overlay window, a drag and its lost mouse (`OverlayDragTests`, the mouse's messages posted with a cursor of the test's own), the menus' entries (`OverlayMenuTests`), the settings file and the sensor client, over a pipe of the test's own serving the recordings, one of them split across reads. `SensorHost` holds those of `src/Thermi.SensorHost`: the pipe server, the service, a device that stalls (`DeviceUpdatesTests`), the series recorder and `thermi-sensors`' command line (`SensorProgramTests`), on sensors that replay a recording, never LibreHardwareMonitor. `OnTop` holds those of `Windows/Topmost.cs`: the overlay ignores what its own process reorders, so `OtherProcess.cs` starts this assembly again on the test's desktop, before xunit starts, to raise a taskbar's window, or another's, over it. `Window` holds those of `src/Thermi/Ui`, the window's side of the page: its process and beacon, its editor over a broken or locked file and undo past outside changes, the fan finder on a fake load, and "Start with Windows" on registry keys of the test's own, never the user's Run key (`TestFeed.cs` is their fake sensor feed). `Acceptance` holds the tests a spec's acceptance steps name; the shared helpers stay at the root.

Windows go on a desktop of the test's own (`TestWindows.OnOwnDesktop`), so a locked screen or another app's window never covers them, and nothing shows on the user's screen. Every process a test starts, `thermi.exe`, this assembly again or `pwsh`, starts through `DesktopProcess` on such a desktop too, so a message box or a crash dialog of it never reaches the user; a repo rule holds both. The tests that run an `OverlayHost` run one at a time (`HostRun.cs`), since its window classes and the handles the leak test counts are the whole process's; they pump its messages on the test's thread, on a recorded snapshot. Its tray icons go to a notification area of the test's own (`FakeTray.cs`), which refuses what Windows refuses, its window's mutex has a name of the test's own, and its log is a `ListLogger`, so nothing reaches the user's tray, settings window or log. With `THERMI_TRAY_PNG` set to a folder, `TrayIconsTests` also saves the icons there on a dark and a light taskbar at 100, 150 and 200 %, to look at them.

A test's desktop thread is a single-threaded apartment, as a thread with windows is, whose COM apartment is left and entered again around `SetThreadDesktop`, since it keeps a window of its own on the thread and a thread with a window cannot move.

The Win32 calls only the tests make are generated by CsWin32 from this project's `NativeMethods.txt` into `TestPInvoke`, beside thermi's own `PInvoke`.

`scripts/check.ps1` runs them in their own step, outside the coverage of `src/Thermi.Core`, and shows how much of thermi and thermi-sensors they run, without a gate. Coverlet leaves out an assembly this process loads before the tests start, so `EndingChild.cs` keeps thermi's types out of its initializer.
